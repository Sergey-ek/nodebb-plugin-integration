# NodeBB Integration

Слой интеграции NodeBB с ИИ и MCP.

Плагин подключает NodeBB к семантическому поиску на основе ИИ и предоставляет внешним ИИ-клиентам доступ к функциям форума через Model Context Protocol (MCP).

- **Версия:** 0.6.2
- **Лицензия:** MIT
- **NodeBB:** 4.x
- **Node.js:** >= 22

## Возможности

- MCP-сервер с использованием транспорта Streamable HTTP.
- Отдельный дочерний процесс MCP, управляемый плагином.
- Аутентификация MCP-клиентов через OAuth 2.0 с использованием потока Authorization Code + PKCE (`S256`).
- Поддержка CIMD (Client ID Metadata Documents) для публичных OAuth-клиентов.
- Явное согласие пользователя и управление доступом MCP для каждого пользователя.
- Поддержка статической Bearer-аутентификации для обратной совместимости.
- Отдельный токен аутентификации для внутреннего API NodeBB.
- Настраиваемые адрес привязки, порт и режим аутентификации MCP.
- 15 MCP-инструментов для получения информации о форуме, чтения, поиска и управления содержимым.
- Генерация эмбеддингов OpenAI и семантический поиск.
- Интеграция с векторной базой данных Qdrant.
- Поиск с учётом прав доступа: результаты фильтруются на основании разрешений NodeBB.
- Индексация отдельных сообщений и исключение категорий.
- Режимы OpenAI и Fake в качестве ИИ-провайдера.
- Интерфейс настройки плагина в административной панели NodeBB (ACP).
- Автоматизированные тесты обработчиков API и MCP-инструментов.

## Требования

- Node.js >= 22.
- npm >= 10.
- NodeBB 4.x.
- Работающий экземпляр NodeBB.

Для семантического поиска с использованием ИИ дополнительно требуются:

- API-ключ OpenAI.
- Доступный экземпляр Qdrant и коллекция, настроенная для используемой плагином модели эмбеддингов.

MCP-инструменты, не зависящие от семантического поиска, можно использовать независимо от настроек OpenAI и Qdrant. Инструмент `search_knowledge` требует наличия провайдера OpenAI и Qdrant.

## Установка

Установите плагин через интерфейс администрирования NodeBB или стандартным способом установки плагинов NodeBB.

Для ручной установки:

```bash
cd /path/to/nodebb
npm install nodebb-plugin-integration
```

Соберите и перезапустите NodeBB стандартным для вашей установки способом.

После установки откройте:

**NodeBB ACP → Plugins → NodeBB Integration**

Настройте необходимые параметры и сохраните настройки.

## Настройка

Настройки плагина управляются через административную панель NodeBB (ACP).

### ИИ-провайдер

Плагин поддерживает два режима работы:

- **OpenAI** — включает генерацию эмбеддингов и семантический поиск.
- **Fake** — отключает обращения к сервису OpenAI. Семантический поиск в этом режиме недоступен.

Для семантического поиска настройте API-ключ OpenAI, параметры эмбеддингов и подключение к Qdrant в соответствии с вашей инфраструктурой.

Настройки эмбеддингов по умолчанию:

| Параметр | Значение по умолчанию |
|---|---|
| Модель эмбеддингов | `text-embedding-3-small` |
| Размерность эмбеддингов | `1536` |
| Коллекция Qdrant | `nodebb_knowledge` |

### Поиск и индексация

Плагин использует эмбеддинги для индексации содержимого форума, а Qdrant — для хранения и поиска векторов.

Результаты поиска возвращаются не только на основании векторного сходства. Перед возвратом результата плагин проверяет, имеет ли аутентифицированный OAuth-пользователь или настроенный служебный пользователь в режиме Legacy право на чтение соответствующего сообщения и темы.

Параметр **Excluded Categories** позволяет исключить выбранные категории из семантического поиска.

Перед возвратом содержимого сообщения плагин проверяет полученные метаданные сообщения по данным NodeBB. Qdrant используется в качестве векторного индекса, а NodeBB остаётся источником содержимого сообщений и информации о правах доступа.

## MCP-сервер

Настройки MCP находятся в разделе:

**NodeBB ACP → Plugins → NodeBB Integration**

| Параметр | Описание |
|---|---|
| Enable MCP | Включение или отключение MCP-сервера |
| Authentication mode | Режим аутентификации: OAuth 2.0 или Legacy Bearer Token |
| Bind address | Адрес, на котором MCP HTTP-сервер принимает подключения |
| Port | Порт MCP HTTP-сервера |
| NodeBB URL | Внутренний URL для подключения MCP-процесса к NodeBB |
| Bearer token | Общий токен аутентификации; используется только в режиме Legacy Bearer |
| Service user UID | Учётная запись NodeBB, от имени которой выполняются операции MCP; используется только в режиме Legacy Bearer |

Режим OAuth 2.0 используется по умолчанию. Каждый MCP-клиент авторизует конкретного пользователя NodeBB. После этого операции MCP выполняются от имени этого пользователя и с учётом его прав доступа.

Режим Legacy Bearer Token сохранён для обратной совместимости. В этом режиме все клиенты используют общий настроенный Bearer-токен, а операции MCP выполняются от имени указанного служебного пользователя.

Настройки подключения MCP по умолчанию:

```text
Bind address: 127.0.0.1
Port:         3100
NodeBB URL:   http://127.0.0.1:4567
```

Адрес привязки по умолчанию ограничивает подключения к MCP локальным интерфейсом. Изменяйте его только в том случае, если удалённый доступ действительно необходим и сетевой периметр надёжно защищён.

При публикации MCP через обратный прокси внешний адрес `/mcp` должен быть доступен по HTTPS.

### Обратный прокси Nginx

Добавьте этот блок внутрь существующего HTTPS-блока `server` вашего форума. Сохраните обычный прокси-маршрут NodeBB (обычно `location /`): через него NodeBB должен продолжать обслуживать OAuth-маршруты авторизации и метаданных.

```nginx
location = /mcp {
    proxy_pass http://nodebb:3100;
    proxy_http_version 1.1;

    proxy_set_header Host $host;
    proxy_set_header X-Real-IP $remote_addr;
    proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
    proxy_set_header X-Forwarded-Proto $scheme;
    proxy_set_header Connection "";

    # Необходимо для ответов MCP Streamable HTTP.
    proxy_buffering off;
    proxy_request_buffering off;
    proxy_cache off;

    # Тайм-ауты для длительных MCP-запросов и потоковых ответов.
    proxy_read_timeout 3600s;
    proxy_send_timeout 3600s;
}
```

Пример предполагает, что Nginx и контейнер NodeBB подключены к одной Docker-сети, а MCP-процесс доступен по адресу `nodebb:3100`. Для такой схемы в ACP плагина укажите **Bind address** = `0.0.0.0`. Не публикуйте порт 3100 на внешнем интерфейсе хоста: он должен быть доступен только внутри приватной Docker-сети.

Если Nginx работает непосредственно на том же хосте и использует общее сетевое пространство с MCP-процессом, укажите `proxy_pass http://127.0.0.1:3100;` и оставьте **Bind address** = `127.0.0.1`.

Здесь используется точное совпадение `location = /mcp`, а у директивы `proxy_pass` нет URI-суффикса, поэтому исходный путь `/mcp` передаётся без изменений. Не направляйте OAuth-маршруты `/.well-known` на порт 3100: их обслуживает NodeBB через обычный прокси-маршрут форума.

Плагин автоматически генерирует отдельный случайный токен для своего внутреннего API. Этот токен используется только для взаимодействия между MCP-процессом и плагином NodeBB. Он отличается от токена доступа клиента и никогда не должен передаваться MCP-клиентам.

В режиме OAuth пользователи могут управлять доступом MCP и отзывать разрешения отдельных клиентов на странице своей учётной записи NodeBB:

`/user/<userslug>/integration`

## Аутентификация MCP

### OAuth 2.0

OAuth 2.0 является режимом аутентификации по умолчанию.

Плагин реализует поток OAuth 2.0 Authorization Code с PKCE (`S256`). MCP-клиенты являются публичными клиентами и не используют `client_secret`.

Сервер авторизации публикует свои метаданные по адресу:

`https://forum.example.com/.well-known/oauth-authorization-server`

Плагин поддерживает Client ID Metadata Documents (CIMD). Клиент идентифицирует себя с помощью HTTPS URL, указывающего на документ со своими метаданными.

При подключении нового клиента:

1. Плагин получает и проверяет метаданные клиента.
2. Пользователь проходит аутентификацию в NodeBB.
3. NodeBB отображает страницу подтверждения доступа.
4. После подтверждения пользователем клиент автоматически получает разрешение на работу от имени этого пользователя.

Для ранее одобренного клиента повторное подтверждение не требуется, пока его разрешение на доступ и метаданные клиента остаются действительными. Если разрешение отозвано или метаданные клиента изменились, пользователь должен повторно подтвердить авторизацию.

Каждый OAuth-клиент действует от имени пользователя NodeBB, который его авторизовал. При выполнении операций MCP применяются права доступа этого пользователя в NodeBB.

Сроки действия OAuth-токенов:

| Токен | Срок действия |
|---|---|
| Код авторизации | 5 минут |
| Токен доступа | 15 минут |
| Токен обновления | 30 дней |

При использовании токены обновления заменяются новыми.

Пользователи могут управлять доступом MCP на странице своей учётной записи NodeBB. Можно полностью отключить доступ MCP или отозвать разрешения отдельных клиентов. Отключение доступа на уровне пользователя аннулирует существующие токены. После повторного включения доступа клиентам необходимо пройти авторизацию заново.

### Legacy Bearer Token

Режим Legacy Bearer Token предусмотрен для обратной совместимости.

В этом режиме все MCP-клиенты используют один и тот же настроенный статический Bearer-токен. Операции MCP выполняются от имени учётной записи NodeBB, указанной в параметре Service user UID.

Используйте этот режим только в том случае, если требуется совместимость с существующей интеграцией, использующей Bearer-токен.

## MCP-инструменты

MCP-сервер предоставляет 15 инструментов:

| Инструмент | Описание |
|---|---|
| `get_forum_info` | Получение общедоступной информации о форуме |
| `get_post` | Чтение сообщения |
| `get_topic` | Получение метаданных темы |
| `get_user` | Получение общедоступных полей профиля пользователя |
| `search_knowledge` | Семантический поиск по проиндексированному содержимому форума |
| `create_topic` | Создание темы |
| `delete_topic` | Мягкое удаление темы |
| `restore_topic` | Восстановление темы |
| `list_topics` | Получение списка доступных тем |
| `create_post` | Создание ответа в теме |
| `edit_post` | Редактирование сообщения |
| `delete_post` | Мягкое удаление сообщения |
| `restore_post` | Восстановление сообщения |
| `delete_user_posts` | Мягкое удаление ответов пользователя пакетами |
| `list_posts` | Получение списка сообщений в теме |

Все операции записи используют штатные методы NodeBB и проверки прав доступа.

Инструменты удаления выполняют мягкое удаление, а не безвозвратное удаление данных. Инструмент `delete_user_posts` пропускает первое сообщение каждой темы. Восстановление темы не приводит к автоматическому восстановлению сообщений, которые были удалены отдельно.

Полное описание схем аргументов, значений по умолчанию, ограничений, полей ответов, разрешений, пагинации и примеров приведено в справочнике:

- [Справочник MCP API (английский)](docs/MCP.md)
- [Справочник MCP API (русский)](docs/MCP.ru.md)

## Безопасность

- OAuth 2.0 является режимом аутентификации MCP по умолчанию. Он использует Authorization Code + PKCE (`S256`) и явное согласие пользователя.
- Срок действия OAuth-токенов доступа составляет 15 минут. Токены обновления действуют 30 дней и заменяются новыми при использовании.
- Метаданные OAuth-клиентов загружаются по HTTPS URL CIMD. При получении метаданных плагин проверяет публичные DNS-адреса и TLS-сертификаты.
- Пользователи могут полностью отключить свой доступ MCP или отозвать разрешения отдельных клиентов.
- Режим Legacy Bearer использует общий статический токен и настроенную служебную учётную запись. Используйте его только для обеспечения обратной совместимости.
- Для внутреннего API NodeBB используется отдельный автоматически сгенерированный токен. Никогда не передавайте его MCP-клиентам.
- Внутренние маршруты API требуют аутентификации и отключаются при отключении MCP.
- Адрес привязки MCP по умолчанию — `127.0.0.1`.
- Операции чтения и записи используют права доступа NodeBB аутентифицированного OAuth-пользователя или настроенного служебного пользователя в режиме Legacy.
- При семантическом поиске результаты фильтруются с учётом прав пользователя, от имени которого выполняется запрос.
- При поиске пользователей возвращаются только выбранные поля публичного профиля.
- Секретные значения не включаются в общедоступную информацию о конфигурации плагина.

Используйте HTTPS для внешних MCP- и OAuth-адресов. Не публикуйте токен внутреннего API. В режиме Legacy Bearer защищайте общий токен так же тщательно, как учётные данные, предоставляющие доступ к настроенной служебной учётной записи.

## Разработка

Установите зависимости:

```bash
npm install
```

Выполните проверку синтаксиса:

```bash
npm run check
```

Запустите набор тестов:

```bash
npm test
```

Тесты охватывают аутентификацию API, обработчики API, проверку аргументов и поведение MCP-инструментов.
